# 8. RETRIEVAL ENGINE

THIS is the actual beast part.

---

## Layer 1 — Fast Retrieval

Keyword search.

```text
grep
ripgrep
sqlite FTS
BM25
```

Used for:

* exact commands
* filenames
* error messages
* syllabus
* exam dates

---

## Layer 2 — Semantic Retrieval

Embedding/vector search.

Used for:

* similar conversations
* emotional context
* related problems
* coding patterns

---

## Layer 3 — Deep Reconstruction

When logs exceed context.

This is your important idea.

---

# DEEP SEARCH SYSTEM

If archive > 10M tokens:

```text
split into chunks
```

Example:

```text
archive_1
archive_2
archive_3
...
```

Scout then:

```text
query
↓
identify relevant chunks
↓
spawn retrieval passes
↓
summarize each
↓
merge summaries
↓
recursive refinement
↓
inject final context
```

This is basically:

```text
multi-pass recursive memory reconstruction
```

VERY powerful.

---

# 9. SELF-RESTARTING CONTEXT PASSES

This is your unique idea.

Pseudo flow:

```text
if relevant_logs > context_limit:
    split_logs()
    summarize_part()
    save_partial_memory()
    reload_next_chunk()
    continue_search()
```

This allows:

* effectively infinite memory
* unlimited history search
* recursive analysis

Scout becomes:

```text
context streaming intelligence
```

instead of fixed-window AI.
